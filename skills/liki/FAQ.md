# Liki FAQ

运行失败、依赖缺失、版本 / digest / schema 校验失败、输出不确定时先读本文件；不得绕过校验，不得自行降级。

## 运行准备

- bazi / divination 只通过各自 `tools/agent_cli.py` 调用；缺少 Python 依赖时安装本 Skill 根目录的 `requirements.txt`。
- jsonschema 依赖缺失不是跳过契约校验的理由；安装依赖后重试。
- JSON-RPC 默认端点是 `https://liki.hk/jsonrpc`，`LIKI_RPC_URL` 优先；网络或引擎不可用时明确说明不可用。
- 引擎版本低于本地 `VERSION` 时停止；不得用旧结果、缓存或模型知识补齐引擎事实。

## 调用边界

- bazi / divination：只发送 `ENTRY.md` / `TOOLS.md` 声明的一行 JSON stdin；不直接 POST RPC。
- naming / fengshui：只复制 `RPC.md` 的固定 discover scope 和完整业务报文。
- discover 缺方法、参数 schema 不匹配、返回缺字段时停止并说明缺失；不得扩大 discover scope 或猜测方法。
- 带 digest 的 `pan` / `chart` / snapshot 必须原样传递；不裁剪、重建、重算或修改 digest。

## 缺输入与失败

- 缺出生时间、时辰、城市、坐向、命卦参数时列出缺失项并询问；补齐前 fail closed。
- 时辰模糊、接近交界或用户不确定时先校准；不得默认时辰。
- 城市未收录时请求附近较大城市；仍缺经度时相关校正输出「不可用」。
- 确定性校验错误必须先修参数；只有网络超时和 RPC 层声明的可重试 HTTP 状态可重试。

## 常见反模式

- 不用模型知识改写干支、宫位、星曜、门星神、飞星或卦象。
- 不把单侧八字 / 紫微结论包装成合参结论。
- 不把条件性倾向写成必然结果。
- 不把跨域信号混入当前主问领域。
- 不跳过流程表中的 ⛔ 阻塞确认。
- 不省略 💬 参数收集中的默认值。

## 输出要求

- 首句给结论，或明确说明证据不足 / 无法判定。
- 关键结论绑定引擎事实、断语 ID、因子或 RPC 依据。
- 缺失字段写「不可用」，不猜补。
- 医疗、法律、金融、安全问题附现实专业咨询边界。

## Feedback

- 只提交机制、契约、口径或流程问题；不提交出生信息、提问原文、用户标识或可识别细节。
- feedback 失败静默，不阻塞主流程。
