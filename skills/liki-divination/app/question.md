# 问卦总路由

## 路由纪律

- 先锁定一个问题目标；多个独立目标时，请用户选择本次主问题。
- 默认只选一个方法；不自动六爻 + 奇门双排。
- 用户明确指定六爻 / 奇门 / 黄历时，安全放行后优先用户指定。
- 医疗、自伤、怀孕、重大人身或财务风险先分流，不排盘。

## LLM 路由流程

| 步骤 | 类型 | 动作 | 产物 |
|---|---|---|---|
| 1 | 路由 | 识别本次要判断的结果 | 问题目标 |
| 1a | ⛔ 阻塞确认 | 复述目标，建议六爻 / 奇门 / 黄历，并给编号选项；等用户确认后才能起卦或排盘 | 确认的问题和方法 |
| 2 | 路由 | 按下方场景映射选择链路 | 方法与工具链 |
| 3 | 安全 | 高风险现实事项 | 专业帮助 / 紧急帮助，不排盘 |
| 4 | 路由 | 目标混合或不足 | 只问一个问题或给出编号选项 |

## 场景映射

| 场景 | 默认工具链 | 适用 |
|---|---|---|
| 事件结果 / 能否成 | `liuyao_snapshot` → `liuyao_ask` | 通过、到账、答应、复合 |
| 事件应期 | `liuyao_snapshot` → `liuyao_ask` | 何时有结果 |
| 策略决策 | `qimen_snapshot` → `qimen_ask` | 该不该做、怎么选 |
| 方向 / 方位 | `qimen_snapshot` → `qimen_ask` | 路径、方位 |
| 行动时机 | `qimen_snapshot` → `qimen_ask` | 现在是否推进 |
| 择日 | `huangli_days` | 哪天适合 |
| 长期命局 | 转八字命理技能，不临时起卦 | 终身趋势、行业、婚姻整体 |

## 用神与 snapshot 边界

- 不熟悉六亲取用时用 `matter`，由 engine 场景表映射用神。
- 有明确取用经验且需要精确控制时用 `yong_shen` 显式指定；显式 `yong_shen` 优先于 `matter` 自动推导，但二者仍只能传一项。
- 同一 immutable snapshot 可切换 `yong_shen` 或 `matter` 从不同角度解读，但原始事件不变时结果最可靠。
- 新事件、新时间、新决策必须新建 snapshot；auto 模式会重新起卦，不得伪装成同一卦。

## 线上起卦

纯文字对话无法实际摇硬币时，默认推荐 `liuyao_snapshot(mode=auto)`，由 engine 用安全随机数起卦。先告知用户线上起卦没有实地摇卦的仪式性和传统局限，由用户确认接受后再继续。

### 交互模板

```text
1a ⛔ 只输出：你要问的是「{复述问题}」。我建议用{六爻 / 奇门 / 黄历}，因为{原因}。选项 1.对，就问这个，开始 2.我想问的其实是{可能含义}。停在这里，等用户确认后起卦。
```

用户要求双法时，先确认两个维度；合参只做“六爻独立看结果、奇门独立看策略”的分层对照，不混算吉凶。

## 输出顺序

1. 首句给直接方向：可成 / 难成 / 可行但需调整 / 时机未明。
2. 列 2-3 条 engine 事实依据（用神、世应、动爻、应期候选等）。
3. 再展开分析与建议。
