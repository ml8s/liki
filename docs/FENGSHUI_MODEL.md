# 风水领域模型与分层

本文定义 `liki-fengshui` 的领域边界、RPC 契约和解读边界。风水域当前包含两个正交子域：

- **八宅**：以出生年份和性别推导命卦，判断东四 / 西四命、四吉四凶方与门主灶配合。
- **玄空**：以宅运起盘日期和二十四山坐向排山向飞星，判断元运、旺衰、流年叠加与收山出煞。

两个子域不混盘、不互推、不与八字四柱合参。

## 1. 分层

| 层 | 职责 | 当前实现 |
|---|---|---|
| App 场景层 | 区分布局、流年、元运等用户目标，并确定八宅或玄空分支 | `app/fengshui.md` |
| Domain 知识层 | 解释游年九星、飞星组合、元运旺衰和传统化解思路 | `domains/bazhai/**`、`domains/xuankong/**` |
| Engine 事实层 | 命卦、宅向、飞星、元运、流年飞星与 digest 的确定性计算 | `bazhai.*`、`xuankong.*` RPC |
| LLM 解释层 | 只用返回事实与领域翻译表组织结论和建议 | 不自行排盘，不改方位、星曜和吉凶判定 |

风水没有 Python 编排层。RPC 输入少、领域事实固定、无跨方法投影和断语长表求值；直接调用 RPC 可以保持调用链最短。若后续出现可复用 snapshot、复杂证据聚合或多 RPC 组合，才应评估新的编排层。

## 2. 路由与输入边界

| 用户目标 | 方法链 | 必要输入 |
|---|---|---|
| 命卦、方位吉凶、门主灶 | `bazhai.chart` → `bazhai.layout` | 出生公历年份、性别；实际门 / 主 / 灶卦 |
| 宅运盘、旺山旺向、上山下水 | `xuankong.chart` | 宅运起盘日期、坐山、向山 |
| 流年飞星与宅盘凶星叠加 | `time.now`（必要时）→ `xuankong.chart` → `xuankong.liunian` | 目标年份、完整宅盘与 `chart_digest` |

输入语义：

- 八宅只需出生年份和性别；不要向用户索要出生时辰。
- 玄空的 `period_date` 是宅运起盘日期，通常取建成、入住或改宅日期；不得用命主出生日期替代。
- 玄空不使用命主出生年份、性别或命卦；八宅不排二十四山飞星盘。
- 坐山与向山都是二十四山索引 `0-23`，且必须满足 `xiang_shan == (zuo_shan + 12) % 24`。

缺关键输入时先澄清，不得用默认出生时间、默认坐向或默认年份替代领域事实。

## 3. 八宅领域对象

### MingGua

命卦是由出生年份和性别推导的人卦事实。

```json
{
  "gua": {"index": 7, "name": "兑", "wuxing": "金", "yin_yang": "阴"},
  "group": "西四命"
}
```

`index` 是洛书数；洛书五没有独立卦，按领域规则男寄坤、女寄艮。`group` 只能是东四命或西四命。

### BaZhaiDirections

`bazhai.chart.ba_zhai_dirs` 输出命卦对应的四吉四凶方位。四吉是生气、天医、延年、伏位；四凶是祸害、五鬼、六煞、绝命。每个游年星绑定具体方向，LLM 不得按卦名重排。

### DoorMasterStove

`bazhai.layout` 输入门、主、灶三类布局事实。输入是命卦和门 / 主 / 灶卦，输出包括：

| 对象 | 含义 |
|---|---|
| `group` | 命卦所属的东四宅 / 西四宅 |
| `ming_gua` | 参与配合的命卦 |
| `door` / `master` / `stove` | 各自方向、卦名、五行、游年九星、rating、group 与 match |

`match` 是东四 / 西四同组的粗判；`youxing` 是更细的游年九星。解释时以 `youxing` 为主，不能用 `match` 覆盖 `youxing`。多点位结论必须逐项引用，不做单一总分。

## 4. 玄空领域对象

### SanYuanYun

元运事实来自 `xuankong.chart.yun`，包括当前年份、上元 / 中元 / 下元、运数、运名和本运起止年。三元九运以 1864 年为一运起点，每运二十年。

### Chart

玄空宅盘是一次确定性排盘结果，核心字段包括：

| 字段 | 含义 |
|---|---|
| `zuo_shan` / `xiang_shan` | 二十四山坐向索引 |
| `gong_wei` | 九宫的运星、山星、向星 |
| `wang_shan` / `wang_xiang` | 旺山、旺向 |
| `shan_xing` / `xiang_xing` | 双星会坐、双星会向 |
| `xia_shui` | 上山下水 |
| `fu_yin` | 伏吟信号 |
| `xing_jia_hui` | 双星加会事实 |
| `shou_shan_chu_sha` | 正神 / 零神、收山、出煞与评估 |
| `chart_digest` | canonical SHA-256 完整性摘要 |

`chart_digest` 不是安全签名，而是防字段缺失、防手工拼装和防静默改盘的完整性摘要。`xuankong.liunian` 传入宅盘时必须先通过 digest 校验；校验失败返回错误，不得降级为只排流年或重建宅盘。

### LiuNianResult

流年盘包括年份、入中星和九宫飞星。传入宅盘后，engine 会输出 `house_overlay`，把流年凶星落宫与宅盘该宫的运 / 山 / 向三星对照。LLM 只能引用 engine 给出的叠加结果，不能自行把流年星“飞入”宅盘。

## 5. 结论与证据边界

1. 首句给布局或流年判断，随后列命卦、飞星、元运依据。
2. 每个建议必须绑定具体方位和 engine 事实。
3. 专断因子优先；冲突因子并列解释。多个同向因子才可形成综合判断，不得把单星、单宫夸大为全宅结论。
4. 凶方或冲煞结论同时给可行动调整；调整表述为传统文化视角，不承诺结果。
5. 实体砂水、建筑结构、采光通风等未输入信息标注为未验证，不得由飞星反推出确定事实。

## 6. 硬约束

1. 八宅和玄空事实只能由 RPC 计算；LLM 和文档只做翻译与解释。
2. 不把八宅命卦用于玄空，也不把八字用神、日主强弱或紫微宫位引入风水判断。
3. 玄空坐向必须相对；`chart_digest` 必须原样保留。
4. 无完整输入时不输出确定盘；无实际砂水时不输出确定风水效应。
5. 建筑、安全、法律、医疗问题引导对应专业人员；不做宿命化或绝对化表述。
