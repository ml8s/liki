# 起名领域模型与分层

本文定义 `liki-naming` 的领域对象、RPC 契约和生成边界。起名是八字用神策略的下游应用，不是独立命盘体系；它只使用八字，不引入紫微、六爻、奇门或风水合参。

## 1. 分层

| 层 | 职责 | 当前实现 |
|---|---|---|
| App 场景层 | 区分通用起名、外国人起中文名、自选名评估 | `app/naming.md`、`app/foreign.md`、`app/selfcheck.md` |
| Domain 知识层 | 选择用神候选、过滤字池、判断出处等级与音韵审美 | `domains/bazi/**`、`domains/qiming/**` |
| Engine 事实层 | 八字排盘、用神三派候选、字库属性、字池、组名和名字校验 | `bazi.*`、`qiming.*` RPC |
| LLM 生成层 | 在返回字池内筛字、组名、解释优点和可商榷点 | 不新增字、不重算五行、不创造评分体系 |

起名没有 Python 编排层。它没有独立 snapshot、断语长表或跨盘投影；核心链路是少量 RPC 的顺序组合。直接 RPC + 领域文档可以避免多余的中间层。

## 2. 主链路

### 有出生信息

```text
bazi.chart
  → bazi.fullchart
  → 选择用神 / 喜神 / 忌神策略
  → qiming.pick
  → 在 chars 内过滤
  → qiming.compose
  → qiming.check
```

`bazi.fullchart` 返回扶抑、格局、调候三派候选。起名按 `domains/bazi/yongshen.md` 复核从格、冬夏调候、清透格局和普通命局，最终只采用一组 `yong / xi / ji`，并说明所选学派和取舍理由。

### 无出生信息

可按用户明确期望的五行取字；用户选择“不限”时合并多个字池。输出必须明确说明“未评估用神”，不得虚构补益方向。

### 自选名评估

自选名直接调用 `qiming.check`。若用户提供出生信息，可先排八字并传入用神、喜神、忌神；否则只给字库、音韵事实，不给五行补益结论。

## 3. 核心对象

### YongShenStrategy

用神策略是起名的五行目标，不是新的命盘对象。

| 字段 | 来源与含义 |
|---|---|
| `yong` | 最优先补益的五行 |
| `xi` | 次优先五行 |
| `ji` | 避免的五行 |
| 所选学派 | 扶抑、格局或调候 |
| 复核依据 | 从格、调候、格局透干或扶抑验证 |

三派候选一致时合并；冲突按领域文档的裁决顺序处理。engine 候选缺失时输出“用神未评估”，不在 LLM 侧重排八字。

### CharacterFact

字库事实由 `qiming.char` 或 `qiming.check.characters` 返回，包括字、五行、现代规范笔画、部首、拼音和声调。LLM 不得修改这些属性，也不得用网络传闻或五格笔画规则覆盖 engine 字库。

### CharPool

`qiming.pick` 按五行返回候选字池：

```json
{
  "wuxing1": "木",
  "pools": [
    {"slot": "first", "chars": ["..."]},
    {"slot": "second", "chars": ["..."]}
  ]
}
```

生成类候选只能来自对应 `chars`。用户避讳字、生僻字、负面字和不合语义字可以删除；领域外的新字不能加入。必含字不在字池时报告冲突，请用户调整必含字或五行策略。

### CandidateName

候选名是可评估的名字对象，双字名由 `first` 与 `second` 池组合，单字名只来自 `first` 池。推荐候选应同时呈现：

1. 名字与拼音；
2. 五行与用神 / 喜神关系；
3. 音韵事实与潜在谐音；
4. 寓意或出处；
5. 一个优点和一个可商榷点。

`qiming.compose` 只负责机械组合。LLM 需要从组合结果中精选 5-8 个首轮候选，并保留代表性不推荐名单与淘汰原因。

### NameEvaluation

`qiming.check` 返回最终评估事实：

- `valid`：是否通过字库和负面字校验；
- `errors`：长度、字库缺失或负面字等原因；
- `characters`：逐字事实；
- `phonetic.tones`：声调序列；
- `wuxing.yong / xi / ji`：是否命中传入的五行策略。

invalid 候选必须丢弃或明确标注，不得继续推荐。没有传入五行策略时，`wuxing` 命中字段不可虚构。

## 4. 出处与表达边界

| 等级 | 判定与表达 |
|---|---|
| 直接典故 | 必须给可核书名、篇名和原文；优先从原句取字重组，不整词照搬 |
| 字义联想 | 只说明字义、气质和组合关系，不冒充经典 |
| 现代审美 | 说明音韵、字形和当代使用感受 |
| 未确认 | 记不清或无法核对时显式标注；禁止补作者、书名、篇名或原句 |

表达还须满足：

1. 不给分数、星级或新的吉凶档；
2. 不宣称名字决定命运、相貌或婚姻；
3. 不重复展示的完整候选名，除非用户要求；
4. 外国人中文名保留拼音，英文解释时首次出现的核心术语括注英文；
5. 同音避讳必须有用户提供的读音或 `qiming.char` 拼音证据，默认只避 exact 字。

## 5. 硬约束

1. 排盘、用神候选、字池、字符属性、组合和校验全部来自 RPC。
2. 候选字只能来自 `qiming.pick`；`qiming.compose` 只传字。
3. `qiming.check.given_names` 只传不含姓的名；姓氏只用于展示、音韵审美和谐音讨论。
4. 无出生信息时必须声明“未评估用神”。
5. 起名只用八字；不做紫微合参、六爻合参或风水合参。
6. 出处不可核时降级，不编造；事实缺失时标注不可用，不用默认值补齐。
