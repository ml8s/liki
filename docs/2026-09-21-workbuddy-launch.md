# Liki 上线 WorkBuddy：把命理 Skill 做成可回溯的小型专家系统

> 懂命理，用 Liki。现在也可以在 WorkBuddy 里用了。

这几天我们把 Liki 从一个“能聊命理的 Skill”，继续推进成一个更接近专家系统的工具：排盘交给 Go 天文历算引擎，判断交给规则真值表，结论保留因子、断语和经典出处。用户看到的不只是一段解释，而是一条可以回溯的证据链。

## 这几天完成了什么

### 1. 本命应用域完成重构

`bazi` 现在回到八字方法本位，`natal` 作为本命应用域，统一承载八字、紫微与合参。对外工具收敛为五个：

- `create_birth_chart`
- `analyze_natal`
- `analyze_periods`
- `compare_birth_charts`
- `calibrate_birth_time`

Agent 使用不可变的 `chart_ref` 引用命盘，主题由受控 `topics` 路由，不再把完整盘面反复塞给模型自由发挥。上下文更省，结果更稳。

### 2. 断语体系继续扩张

当前规则表已经达到：

- **824 条断语**
- **889 个条件组**
- **1365 行条件**
- 本命因子 **510 个**，流年因子 **111 个**

这几天补齐了多组真值表缺口，包括官杀取清、配偶星得令、长生周期断语、五行交战与心肝俱弱、肾心不交等复合判断。每一新增条目都先回到命理逻辑复核，再做结构化落表。

### 3. 工程门槛全绿

Liki 的质量门槛不是“看起来能跑”，而是：

- Python 测试 **1359** 个通过
- RPC smoke **115** 项通过
- 160 道命理题规则覆盖检查中，零命中题为 **0**
- `make gate` 覆盖静态检查、数据契约、文档契约、Python 测试、Go 测试、集成测试和本地端到端验证

命理系统最容易变成“说不清为什么”。我们把可测性、契约和证据链放在产品核心，就是为了避免这个问题。

### 4. Aipay 升级为先使用后付费

Liki 现在采用清晰的 Aipay 履约模式：

- 服务完成后发起支付宝 AI Pay 支付；
- 未支付仍可继续使用，支付是契约履行，不设功能门槛；
- `402 Payment-Needed` 交给官方 `alipay-payment-skill` 处理；
- 支付完成后，本地原子保存回执，后续会话减少重复提示。

Skill 只负责业务触发、凭证保存和优雅降级，支付协议交给支付宝官方能力。

## 上线 WorkBuddy

**Liki 已上线 WorkBuddy。**

在 WorkBuddy 里，用户可以直接调用 Liki 处理四类问题：

| 领域 | 可以问什么 |
| --- | --- |
| 命理 | 八字、紫微、婚姻、事业、财运、健康、学业、大运流年、合盘 |
| 起名 | 宝宝起名、成人改名、外国人中文名、名字评估 |
| 问卦 | 六爻成败、奇门策略、应期判断 |
| 风水 | 八宅命卦、玄空飞星、家居布局、流年风水 |

WorkBuddy 场景下的价值很直接：不用自己拼报文、查黄历、理解复杂排盘参数。只要按自然语言提问，Liki 会收集必要信息、调用工具、解释规则依据，并给出条件性结论。

## Liki 不做什么

Liki 不是“AI 大师”，也不承诺改运。它做的是把八字、紫微、六爻、奇门、黄历和风水的传统判断流程工程化：

- 引擎负责计算；
- 规则表负责判断；
- LLM 负责组织解释；
- 命理结论保持传统文化视角；
- 涉及医疗、法律、金融等现实决策时，会建议咨询相应专业人员。

## 一句话总结

**Liki 正在做的事，是把传统命理从玄谈和话术里拉出来，做成可验证、可回溯、可测试的 Agent Skill。现在，它已经登陆 WorkBuddy。**
