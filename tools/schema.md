# 断语库 schema v3（三层：常量表 + 因子真值表 + 断语真值表）

> 架构原则（决策纪要）：
> 1. **规则只由表定义**——engine 只做机械匹配/求值，命理知识 100% 在表
> 2. **单一来源 constants.json**——原子知识（五行生克/墓库/日支神煞/紫微主星煞星等）全在 json，代码零命理知识
> 3. **真值表驱动**——因子表（factors.csv）生成因子快照，断语表匹配快照出断语
> 4. **双术数真分开**——bazi 表纯八字因子、ziwei 表纯紫微因子（check_schema 交叉校验防回潮）
> 5. **结论 = 命理表达**——评测状态标签在测试层映射，skill 数据纯命理
> 6. **判题逻辑不混入规则引擎**——程序只输出双盘断语，综合裁决 agent 做

## 数据流

```
birth-info
  │
  ▼
build_factors（读 rpc 排盘数据 → 十神/五行/宫位聚合）
  │
  ▼
evaluate_factors（factors.csv 真值表 → 因子快照 dict，键=因子名）
  │
  ├─ 本命：match(断语表 csv, 因子快照) → 各域断语 {八字: [...], 紫微: [...]}
  └─ 流年：evaluate_liunian_factors（factors_liunian.csv）→ 应期候选年
```

## 二、因子真值表（factors.csv / factors_liunian.csv）

| 列 | 含义 |
|---|---|
| 因子 | 因子名（快照键） |
| 术数 | bazi / ziwei（双术数隔离） |
| 原子列 | 列名即 DSL `算子[参数]`——值 `1` 为该原子成立的条件 |
| 原语直通 | 该因子=某原子直接计算值（非 0/1 组合） |
| 依据 | 命理依据 |

**匹配规则**：一行的所有原子列值 == 原子实际值 → 因子=1；多行=或（任一命中即 1）；未命中=0。
引用本命因子（无 `[]` 的列）= 引用快照中已求值的因子值。

## 三、断语真值表（tools/bazi/*.csv + tools/ziwei/*.csv，19 域）

| 列 | 含义 |
|---|---|
| id | 断语唯一标识（如 hun_101 / xue_201） |
| 事件 | 领域事件（学历层次/婚姻状态/事业档位/职业类型…） |
| 约束列 | 因子名 → 期望值（0/1 或字符串枚举） |
| 结论 | **命理表达**（如"财星透干得地——婚可成"——非评测状态标签） |
| 依据 | 断语依据（含代表题） |
| 经典原文 | 古籍出处（全量覆盖——check_schema 校验） |

**匹配规则**：约束列值 == 因子快照值（全部相等即命中）。**无 any_of / 优先级 / `>=N`**——组合逻辑在因子表拆行表达，确定性靠断语表行序（命理师按确定性排序，程序不排序）。

---

## 四、校验（check_schema.py）

1. 约束键 ∈ 因子全集（factors.csv 因子名）
2. 跨术数交叉——bazi 表纯八字因子、ziwei 表纯紫微因子
3. 结论标签回潮防——结论须命理表达（评测标签在测试层映射）
4. 必填列（结论/依据/经典原文）+ 经典原文覆盖率 + id 唯一

**改表后跑 `bash tests/check.sh`（schema 校验 + 可选 --full 数据检查）。**
